The OpenKodo CLI is the `openkodo` command-line interface for scripting a running OpenKodo editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, share HTML/Markdown artifacts, and control OpenKodo-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → OpenKodo CLI](/docs/settings). The command is `openkodo` on Linux, macOS, and Windows — see [Install → Linux](/docs/install#linux).

Agents can install the matching OpenKodo CLI skill with:

```bash
npx skills add https://github.com/OpenKodo/openkodo --skill openkodo-cli
# headless / no Settings UI:
openkodo skills install --skill openkodo-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable OpenKodo skill, including `openkodo skills install` / `openkodo skills update`.

## Install & verify

```
command -v openkodo
openkodo status --json
```

## Worktree commands

```
openkodo worktree ps --json
openkodo worktree create --repo id:<repoId> --name my-task --issue 123 --json
openkodo worktree create --repo id:<repoId> --name review-pr-123 --pr 123 --json
openkodo worktree current --json
openkodo worktree set --worktree active --comment "reproduced bug" --json
openkodo worktree set --worktree active --gitlab-issue 42 --gitlab-mr 77 --json
openkodo worktree set --worktree active --pr null --json
openkodo worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [OpenKodo CLI reference](/docs/cli/reference).

## Terminal commands

```
openkodo terminal list --json
openkodo terminal read --json
openkodo terminal send --text "npm test" --enter --json
openkodo terminal wait --for tui-idle --timeout-ms 30000 --json
openkodo terminal create --worktree path:/projects/app --command "npm test" --json
openkodo terminal split --direction vertical --command "npm run dev" --json
```

`terminal send` is for shells, dev servers and REPLs. To message another agent, use `openkodo orchestration send`; for tracked multi-agent work, use [Orchestration](/docs/cli/orchestration).

## File commands

Open files and diffs as tabs in their OpenKodo worktree from a shell. They open without changing what you are looking at; add `--focus` to be brought to the file:

```
openkodo file open src/App.tsx
openkodo file diff src/App.tsx --staged
openkodo file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `openkodo tab profile`; start with `openkodo tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `openkodo automations` to create, inspect, run, and remove scheduled OpenKodo tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Share HTML or Markdown as public view links through the signed-in OpenKodo account (`openkodo artifacts share|update|list|delete`). Publishing follows **Settings → Artifacts → Allow publishing public artifact links**: on by default for new profiles, while profiles created before this default keep their previous setting. Command details: [CLI reference → Artifacts](/docs/cli/reference#artifacts).

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
openkodo goto --url https://example.com --json
openkodo snapshot --json     # returns refs like @e1, @e3
openkodo click --element @e3 --json
openkodo fill --element @e1 --value "user@example.com" --json
openkodo screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
openkodo set device --name "iPhone 12" --json
openkodo screenshot --json
```

## Mobile emulator

The CLI can also drive an iOS Simulator through OpenKodo's mobile emulator bridge. It is scoped to the active worktree, so agents and scripts can attach a simulator, list the worktree's attached devices with `openkodo emulator list`, tap normalized coordinates, type text, send gestures, rotate the device, and shut it down without leaving OpenKodo.

```
openkodo emulator list --json
openkodo emulator attach "<device-name-or-udid>" --json
openkodo emulator tap 0.5 0.7 --json
openkodo emulator type "hello" --json
openkodo emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --json
openkodo emulator rotate landscape_left --json
openkodo emulator kill --json
```

Use `--worktree <selector>`, `--device <udid-or-name>`, or `--emulator <id>` when a script needs an explicit target.
